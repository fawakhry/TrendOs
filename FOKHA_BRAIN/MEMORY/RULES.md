# Fokha Rules — Global Only

> قواعد عامة مشتركة بين المشاريع. لا تستخدم كبديل عن قواعد أي مشروع.
> Updated: 2026-09-12.

| Rule | Scope |
|---|---|
| التقط الفكرة سريعًا ثم نظّمها لاحقًا. | Fokha / Workflow |
| كل مشروع له Source of Truth مستقل ومسار دخول موثق. | Fokha / Routing |
| فرّق دائمًا بين المخطط والمجهز والمختبر والمنشور والمتحقق فعليًا. | Fokha / Evidence |
| الأمان ونزاهة البيانات يسبقان السرعة. | Fokha / Execution |
| لا تمحُ التاريخ الصحيح أو الفشل؛ استخدم supersede والتعلم السلبي. | Fokha / Memory |
| استخدم IDs ثابتة وروابط مرجعية بدل الاعتماد على الاسم فقط. | Fokha / Linking |
| الـAI ينظم ويقترح ولا يخترع الحقائق الحية. | Fokha / AI Authority |
| أي تغيير مؤثر يحتاج تحققًا ومسار رجوع واضحًا. | Fokha / Safety |
| قلل العمل اليدوي بالأتمتة مع فصل التجهيز عن التفعيل. | Fokha / Automation |
| الشغل المكتمل يمكن تحويله إلى Evidence ثم Lessons ثم Knowledge Candidates. | Fokha / Learning |
| قبل تعديل نظام شغال، افحصه وحافظ على الوظائف القائمة ونفذ Patch صغيرًا. | Fokha / Execution |
| عند تعدد الحلول المتقاربة، فضل الأبسط والأقل تكلفة والأسهل تشغيلًا إذا لم يوجد مانع موثق. | Fokha / Technical Choice |
| واجهات التشغيل اليومية يجب أن تراعي صلاحيات الدور وعدم كشف بيانات حساسة لغير المصرح. | Fokha / UX & Authorization |
