# Fokha Working Standard — Portfolio Only

> Updated: 2026-09-12 after separating project memories.

## Core operating rules

1. FOKHA_BRAIN is a portfolio/index layer, not a project database.
2. Every project keeps its detailed memory inside its canonical Repository/Branch.
3. Fokha may keep only: project name, broad status, canonical source, canonical branch, and truly cross-project principles.
4. Project-specific Decisions / Rules / Cases / Assets / Knowledge / Negative Learning stay inside the project.
5. When a user asks to work on a project, open that project's canonical source before analysis or execution.
6. Use `FOKHA_BRAIN/MEMORY/PROJECTS.md` as the high-level routing registry.
7. Do not copy project detail into Google Sheet or GitHub Fokha memory merely because it was discovered during analysis.
8. If a project insight is genuinely reusable across projects, store only a concise generalized principle in Fokha and keep the original evidence in the project.
9. Runtime Evidence inside a project outranks Fokha summaries.
10. Keep secrets, credentials, sensitive private data, and customer assets out of public GitHub.

## Capture behavior

- Raw Fokha/global idea -> may go to Fokha working memory.
- Project-specific idea/decision/rule -> goes to that project's canonical memory.
- Project routing update -> update `PROJECTS.md` / `SOURCE_LINKS.md` at high level only.
- Cross-project principle -> may update `RULES.md`, `KNOWLEDGE.md`, `THINKING_MODEL.md`, or `NEGATIVE_LEARNING.md` only in generalized form.

## Authority

`Project Memory / Runtime Evidence > Fokha high-level summary`

## Separation rule

Never recreate a detailed parallel copy of a project's memory inside FOKHA_BRAIN or its Google Sheet working layer.
