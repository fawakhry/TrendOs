# Fokha Extraction Standard — Separated Projects

هذا الـStandard يحكم استخراج المعرفة بدون إنشاء نسخة ثانية من ذاكرة أي مشروع.

## القواعد

1. **Capture first** — التقط الفكرة أولًا ثم نظمها.
2. **Source before interpretation** — احتفظ بالمصدر قبل الاستنتاج.
3. **Explicit beats inferred** — `EXPLICIT_USER > VERIFIED_SOURCE > INFERRED_PATTERN > AI_SUGGESTION`.
4. **Project scope first** — أي معرفة تخص مشروعًا تذهب إلى ذاكرة المشروع الرسمية، لا إلى FOKHA_BRAIN.
5. **Global only in Fokha** — لا يدخل عقل فوخا إلا الخطوط العريضة والمبادئ المشتركة وروابط المصادر.
6. **Stable IDs** — استخدم IDs ثابتة داخل المشروع أو الطبقة العامة حسب النطاق.
7. **No duplicate truth** — لا تكرر الحقيقة الحية في أكثر من مكان.
8. **Preserve history** — استخدم supersede بدل محو التاريخ الصحيح.
9. **Evidence hierarchy** — `LATEST VERIFIED > EARLIER VERIFIED > DEPLOYED > TESTED > IMPLEMENTED > PREPARED > PLANNED > UNKNOWN`.
10. **Promotion rule** — لا تتحول معلومة Project-only إلى `FOKHA_GLOBAL` إلا بدليل عام كافٍ.
11. **Negative learning** — الفشل الخاص بالمشروع يبقى داخل المشروع؛ الخطر العام فقط يمكن تلخيصه في Fokha.
12. **Useful over verbose** — Fokha يحتفظ بالملخصات، والتفاصيل تبقى في المشروع.
13. **Dedupe/update** — حدّث العنصر الموجود بدل إنشاء نسخة مكررة.
14. **Security** — لا تحفظ passwords أو API keys أو tokens أو secrets أو بيانات عملاء خاصة في GitHub العام.
15. **Destination routing** — `PROJECT_MEMORY -> canonical project Repository/Branch`; `FOKHA_GLOBAL -> FOKHA_BRAIN high-level only`.

## قاعدة حاسمة

إذا كان بإمكانك تحديد المشروع الذي تنتمي إليه المعلومة، خزّن التفاصيل في ذلك المشروع. عقل فوخا لا يحتفظ إلا باسم المشروع، مصدره الرسمي، وخلاصة عامة مشتركة عند الحاجة.
