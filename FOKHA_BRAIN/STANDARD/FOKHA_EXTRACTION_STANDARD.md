# Fokha Extraction Standard

هذا الـStandard يحكم كيف يتحول أي مصدر خام إلى معرفة قابلة للاستخدام داخل عقل فوخا بدون خلط الحقيقة بالاستنتاج، وبدون تكرار مصادر الحقيقة الخاصة بالمشاريع.

## القواعد

1. **Capture first** — التقط الفكرة أو المعلومة أولًا، ونظّمها لاحقًا.
2. **Source before interpretation** — احتفظ بالمصدر قبل بناء الاستنتاج.
3. **Explicit beats inferred** — `EXPLICIT_USER > VERIFIED_SOURCE > INFERRED_PATTERN > AI_SUGGESTION`.
4. **Project scope before global scope** — المعرفة تبدأ Project-only ما لم يوجد دليل كافٍ لتعميمها.
5. **Stable IDs** — كل عنصر مهم يحصل على ID ثابت.
6. **No duplicate truth** — عقل فوخا لا يصبح نسخة ثانية من Live Operational Data.
7. **Preserve history** — لا تحذف القديم الصحيح؛ استخدم superseded/replaced/deprecated/invalidated-by-evidence.
8. **Evidence hierarchy** — `LATEST VERIFIED > EARLIER VERIFIED > DEPLOYED > TESTED > IMPLEMENTED > PREPARED > PLANNED > UNKNOWN`.
9. **Promotion rule** — لا تتحول المعرفة إلى `FOKHA_GLOBAL` إلا بدليل عام أو نمط متكرر قوي.
10. **Negative learning** — الفشل والرفض والـregression معرفة يجب الاحتفاظ بها.
11. **Useful over verbose** — استخرج ما يساعد قرارًا أو تنفيذًا أو ربطًا أو تعلمًا، لا مجرد نسخ طويل.
12. **Dedupe/update** — إذا كان نفس العنصر موجودًا حدّث evidence/confidence بدل إنشاء duplicate.
13. **Security** — لا تحفظ passwords, API keys, tokens, secrets أو Credentials حساسة.
14. **Destination routing** — وجّه الناتج إلى Global Thinking Model / Rules / Decisions / Ideas / Project Memory / Knowledge Candidates / Negative Learning / Data References.
15. **Chat behavior** — عندما يُقال لأي Chat: «روح على GitHub عقل فوخا»، يبدأ من `عقل_فوخا.md` ثم `FOKHA_BRAIN/اقرأني_أولا.md` ثم برومبت الاستخراج.
