# عقل فوخا — اقرأني أولًا

> هذا هو مدخل عقل فوخا المؤقت على GitHub إلى أن يتم إنشاء Repository مستقل وخاص باسم `Fokha`.

أي Chat / AI Agent يُطلب منه: **«روح على GitHub عقل فوخا»** أو **«ادخل عقل فوخا»** يجب أن يبدأ من GitHub وهذا الملف قبل أي تحليل أو تنفيذ.

## قاعدة التشغيل الأساسية

**READ FROM GITHUB FIRST -> EXTRACT -> WRITE TO GOOGLE DRIVE IMMEDIATELY -> SYNC ORGANIZED KNOWLEDGE BACK TO GITHUB LATER**

المعنى التنفيذي:

1. دخول عقل فوخا = GitHub أولًا دائمًا.
2. اقرأ الذاكرة والستاندرد وروابط المشاريع من GitHub.
3. اقرأ المصدر المطلوب واستخرج المعرفة والداتا المفيدة.
4. بعد الاستخراج مباشرة، اكتب الناتج في Google Drive داخل `Fokha - Idea Inbox` في التاب المناسب.
5. لا تنتظر مزامنة GitHub حتى تحفظ المعرفة الجديدة؛ Google Drive هو طبقة الكتابة الفورية.
6. تتم مزامنة المعرفة المنظمة والمستقرة إلى GitHub لاحقًا بدون duplication ومع الحفاظ على IDs والمصادر والتاريخ.
7. إذا تعذر الوصول إلى Google Drive، لا تدّع أن الكتابة تمت؛ علّم الناتج `PENDING_DRIVE_WRITE`.

## الهدف

عقل فوخا ليس أرشيف محادثات. الهدف هو تحويل الشغل، المحادثات، القرارات، الأكواد، الملفات، والتجارب إلى معرفة وداتا قابلة لإعادة الاستخدام في الإدارة واتخاذ القرار وتشغيل المشاريع والتعلم منها.

المسار الأساسي:

`RAW INPUT -> EVIDENCE -> EXTRACTED DATA -> GOOGLE DRIVE WORKING MEMORY -> VALIDATION / LINKING -> GITHUB ORGANIZED MEMORY -> REUSE`

## قاعدة الفصل بين السلطات

- **Fokha Brain on GitHub** = نقطة الدخول والسياق التنفيذي العام والمعرفة المنظمة.
- **Google Drive / Fokha - Idea Inbox** = أول وجهة كتابة للمعرفة والداتا المستخرجة الجديدة.
- **Project Memory / Black Box** = الحقيقة التنفيذية الخاصة بكل مشروع.
- **Runtime Evidence** = الأقوى للحالة التشغيلية الحالية عندما يكون متاحًا.
- **Historical conversations/files** = مصادر تعلم وlineage؛ لا تتغلب على Evidence أحدث.
- عقل فوخا يستخرج المعرفة العامة والأنماط والروابط، لكنه لا ينسخ أو يغيّر حقائق المشروع الحية بدون مصدر موثوق.

## عند بدء أي Chat جديد

إذا قال المستخدم: **«روح على جيت هب عقل فوخا»** أو **«ادخل عقل فوخا»** أو ما يعادلها:

1. اذهب إلى GitHub عقل فوخا أولًا.
2. اقرأ هذا الملف كاملًا.
3. اقرأ برومبت الاستخراج والـWorking Standard.
4. اقرأ Memory Index والملفات المرتبطة بالمهمة.
5. حدّد المشروع من `PROJECTS.md` ومصدر الحقيقة من `SOURCE_LINKS.md`.
6. اقرأ المشروع أو المصدر المطلوب من مصدره الرسمي.
7. استخرج المعرفة والداتا المفيدة وفق البرومبت.
8. اكتب الناتج المستخرج فورًا إلى Google Drive `Fokha - Idea Inbox`:
   - فكرة خام -> `INBOX`
   - قرار صريح -> `DECISIONS`
   - قاعدة -> `RULES`
   - نمط تفكير موثق -> `THINKING_MODEL`
   - تحديث مشروع -> `PROJECTS`
   - مصدر/رابط -> `SOURCE_LINKS`
   - معرفة مستقرة قابلة لإعادة الاستخدام -> `KNOWLEDGE`
   - فشل/خطر/طريقة مرفوضة -> `NEGATIVE_LEARNING`
9. افصل بوضوح بين `EXPLICIT_USER`, `VERIFIED_SOURCE`, `INFERRED_PATTERN`, `AI_SUGGESTION`, `UNKNOWN/NEEDS_VERIFICATION`.
10. لا تخترع شيئًا غير موجود في الأدلة.
11. اربط كل عنصر بمصدره أو مرجعه متى كان متاحًا.
12. لا تعتبر الاستخراج مكتملًا إذا كان Google Drive متاحًا ولم تُكتب النتيجة إليه.

## عند قول: «حدّث عقل فوخا من كل المحادثات والمشاريع»

طبّق `STD-010`:

1. ابدأ من FOKHA_BRAIN الحالي.
2. افحص **المصادر التاريخية المتاحة فعليًا**: سياق المحادثات القابل للاسترجاع، ChatGPT Library، وGitHub repositories/ذاكرات المشاريع المتصلة.
3. لا تنشئ Inventory شكليًا فقط؛ استخرج معرفة قابلة للاستخدام وNegative Learning وروابط مصادر ومشاريع.
4. اكتب الجديد إلى Google Drive أولًا مع IDs/Scope/Provenance.
5. Deduplicate: حدّث العنصر الموجود بدل إنشاء نسخة مكررة متى كان نفس المعنى/الـID موجودًا.
6. زامن فقط المعرفة المنظمة وغير الحساسة إلى GitHub.
7. سجّل Checkpoint يوضح ما تم فحصه وحدود التغطية.
8. **ممنوع ادعاء أن كل رسالة تاريخية في الحساب قُرئت حرفيًا إذا لم تكن كل المصادر قابلة للوصول.**
