## DRAFT/EXECUTION — isolated review-only changes
Stacked code [Draft #229](https://github.com/fawakhry/TrendOs/pull/229) adds a **frontend-only** bridge in original `customer-native-browser-transport-v0.js` to request exact pinned Cloudflare HTTPS `POST /v1/customer/native/logout` using the independent held Native bearer and existing server's strict verified response `{success:true,sessionRevoked:true,source:'customer-d1-native-logout-v0'}`. Browser clears its in-memory Native bearer **before awaiting remote CAS acknowledgment**. Only that exact native 200 response returns `serverSessionRevoked:true`. HTTP 401/503, network timeout/failure, invalid body/false-success fail closed `CUSTOMER_NATIVE_LOGOUT_SERVER_UNVERIFIED` and never return a false server acknowledgment. A toggled-OFF source flag can still complete *existing* Native logout without sending the token to Google; after local wipe, a `NATIVE_SESSION_IN_MEMORY` browser-state marker (or `nativeSession:true`) is ALSO blocked from falling back to the Google transport. Non-customer employee calls remain untouched; full OFF behavior remains legacy-compatible **when there is no Native session**.

Existing `app.js customerLogout()` navigation retains legacy behavior while providing a **visible error warning** when a Native server revoke failed/was unverified; the local UI still clears immediately and cannot use the old Native bearer. It never treats a user-visible UI clear as server-side CAS success. The physical server D1 CAS source is unchanged, and there is **NO mounted Worker route**. All JS native flags remain FALSE in the checked-in configuration.
