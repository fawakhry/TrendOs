## What changed: Stage source code, not Production
- New `cloudflare-d1/customer-stage/login-throttle-v0.mjs` exports `CustomerLoginThrottleStageV0`, a **SQLite-backed Cloudflare Durable Object** that uses `ctx.storage.transactionSync()` and `ctx.storage.sql.exec()` to persist BOTH account HMAC and IP HMAC attempt counters in a **single atomic transaction** in the same singleton DO. Fixed 15-minute window. Account limit 5, IP limit 30 attempts per window. A denied attempt does NOT update only one of the two counters. Row keys hold HMAC fingerprints (not raw codes, IPs or passwords), and old inactive rows are pruned. Storage/transaction exceptions and malformed requests fail closed.
- The existing `cloudflare-d1/customer-stage/index.mjs` now exports that DO class and creates the Login handler's rate gate ONLY from `env.CUSTOMER_LOGIN_RATE_STAGE_V0` (the dedicated DO namespace) rather than trusting a pre-existing `env.CUSTOMER_NATIVE_LOGIN_RATE_GATE_V0`. It calls the singleton via internal Stub `.fetch`, requires HTTP 200 with exactly `{allowed:boolean,persisted:true}`, and only then can the ORIGINAL Native Login HTTP gate call the old PBKDF2/D1 CAS session issuer. Missing DO binding -> 503 before touching customer D1. The DO is not publicly routed.
- The **separate** `cloudflare-d1/wrangler.customer-stage.toml` now adds exactly `[[durable_objects.bindings]]` for `CUSTOMER_LOGIN_RATE_STAGE_V0` with `[[migrations]] new_sqlite_classes = ["CustomerLoginThrottleStageV0"]`. All existing Stage and per-route feature flags remain `"false"`; `workers_dev=false`; `preview_urls=false`; still **NO D1 binding, no R2, no secrets and no public routes**. Production `cloudflare-d1/wrangler.toml`, `production-shadow/index.js`, `src/index_v2.js` untouched.
- Original synthetic full login → own orders → revoke session → reject token tests are updated to simulate a **fake DO namespace**. Independent new `tests/customer_stage_durable_rate_limit_off.test.mjs` verifies actual DO class gate logic with a fake SQL transaction interface, 5/15-min account throttle, 30/15-min IP throttle, persistence after DO instance restart, new window, denial without partial updates, namespace handshake and no-DB if gate untrusted, and failure paths. Original Entry660/661/662 disposable SQLite source tests and customer browser/employee regressions remain in no-deploy CI.
- Existing no-deploy Workflow `.github/workflows/trendos-customer-isolated-stage-worker-off-ci.yml` runs both new and old tests and only `npx wrangler@4 deploy --dry-run --config wrangler.customer-stage.toml`. Wrangler source bundling is **not** a Cloudflare deployment and does not create a DO namespace or the independent D1.

## Safety/release gates before real Stage
The code is **not yet a full end-user platform**. The DO binding and migration are written in a Stage config but have NOT been executed in a Cloudflare account. The single global singleton serializes both keys and may become a throughput bottleneck; benchmark before any mass use. There is no production log-in or removed Google action.

A real Stage experiment requires an explicit approved Cloudflare account, independently created disposable Stage D1 with migrations, verified synthetic consented/OTP customer enrollment, trusted Cloudflare IP/Origin ingress (unverified in source), provisioned HMAC secrets, actual DO storage/transaction readback (not just fake SQL), separate Stage UI HTTPS URL, failover/replay/parallel concurrency tests, full order history/ownership parity, and rollback plan. No live account data or secret may be used in offline tests. Never silently repoint the existing browser default production API.
