## ما تغير فعليًا

- `customer-messenger-v1.js/css`: طبقة عرض مألوفة على نمط المحادثات، مع هوية مطبعجي الزرقاء، قائمة طلبات، شات، إدخال رسالة بـEnter، تفاصيل منتج ومرفقات في dialog، مراجعة ملخص المسودة، متابعة الطلب بالبيانات التي يرجعها المسار الأصلي، وبحث في الطلبات.
- `index.html`: تحميل ملفي العرض الجديدين فقط. جميع IDs الأصلية للمنتج والرفع والإضافة والإرسال وتسجيل الدخول محفوظة دون تكرار؛ عناصر الفورم تُنقل ولا تُنسخ.
- `app.js`: hooks عرض محدودة في `renderCustomerHome/Orders/Draft`، ومنع تحميل إعلانات/فروع/كتالوج الشاشة الملغاة في الوضع الجديد فقط؛ cleanup وbusy hooks؛ تحديث معاينة النص دون مرفق في الوضع الجديد. نفس `customerAuthParams` والـAPI الأصلي ما زالا المالكين للأوردر.
- العرض الجديد أزال كروت دخول المصمم/الخدمات المتكررة والكتالوج والفروع/GPS والإعلانات وعرض رسوم تصميم افتراضية من رحلة العميل. وظائفها الأصلية محفوظة للتوافق مع وضع OFF وباقي الأدوار؛ لا حذف أنظمة أو ملفات Stage/اختبارات مهمة باعتبارها «زائدة».
- نص تعليمات العميل والمقاس والعدد ومقاس التيشيرت يظهر في الملخص، مع الاحتفاظ بقواعد الأصل/الدقة/المراجعة في الملاحظات المخزنة. لا أسعار أو إيصالات قراءة أو تاريخ حالات مخترع.
- الصور الجديدة تظهر فقط من `blob:` محلي مصنف image مع `localPreview=true`، عبر عارض الصور الأصلي. مرفق الخادم لا يتحول تلقائيًا إلى رابط Drive أو صورة عامة؛ يعرض اسمه فقط حتى اعتماد المشاهد الخاص. لا تغيير في بايتات الصور أو الخلفية أو الملامح.
- لا نقل لبيانات DEMO أو الـfixture adapter من Site إلى تطبيق العملاء، ولا إنشاء Native dispatcher أو Backend آخر. نص الشات المحلي جزء من ملاحظات البند حتى ضغط الإضافة؛ ليس رسالة مرسلة لموظف.

1. دالة `refreshCustomerPendingPreview` القديمة كانت تحدّث النص بعد وجود مرفق فقط؛ أضيف تحديث النص الخالص عندما تكون واجهة الشات الجديدة معتمدة فقط، وبقي سلوك OFF القديم.
2. اختفاء المقاس من الملخص عند تنقية نص القواعد؛ أضيف استخراج المقاس ومقاس اللبس من نفس مواصفات البند دون تغيير النص المخزن.
3. تنظيف المعاينة بعد نجاح الإضافة حتى لا تبقى نسخة pending مكررة أو blob ملغى؛ تنظيف src في عارض الصور عند انتهاء الجلسة.

## حدود الإطلاق

`TRENDOS_CUSTOMER_CHAT_V1_ENABLED` لم يُفعَّل، و`Code.gs/config.js/Cloudflare D1/R2/T12` لم تتغير. flag غير true يمنع حتى قراءة أو نقل DOM بالـpresenter، وكل CSS محصور في `html.matbagy-ui-enabled #customerView.customer-messenger-active`.

المنسق Native الخاص بالاستئناف ما زال مصدر Stage مؤهلًا محليًا فقط، ولم يُربط بمعالج رفع Google القديم. لذلك **لم نضف زر إعادة محاولة يدّعي idempotency غير موجودة في الكاتب القديم**. P1 الرفع وP0 ملكية الأوردرات/مشاركة الملفات القديمة، scanner/private viewer، وربط Native الرسمي وAccess 403 ما زالت بوابات إنتاج مستقلة.

`SOURCE_UI=INTEGRATED_DEFAULT_OFF`; `REAL_CUSTOMER_RELEASE=NO_GO`; `PRODUCTION_DEPLOY=NOT_PERFORMED`; `PRIVATE_SITE_ACCESS=OWNER_ONLY_UNCHANGED`; `OPENAI_PAID=OFF`. source merge ليس شهادة تحديث أصول Worker الحية. فرع T12 candidate/أصول Cloudflare لا تُستبدل بنسخة app.js من main؛ ذلك يحتاج مقارنة إصدار وإطلاق مستقلين.
