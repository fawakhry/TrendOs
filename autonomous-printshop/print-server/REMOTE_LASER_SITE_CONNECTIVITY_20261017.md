## 1. قرار الربط الفوري: Windows 7 ↔ Windows 7، بلا Ubuntu

**التجربة الأبسط**: Radmin VPN على **جهازَي Windows 7 فقط**، يربطهما عبر الإنترنت دون الحاجة إلى إعداد Port Forwarding، بينما يصل جهاز الليزر بالهوتسبوت، ويظل جهاز المطبعة على الإنترنت المعتاد. وثائق المنتج الرسمية تؤكد توافق Windows 7، التشفير، مجانية البرنامج، وخيار Create network / Join network. راجع EULA قبل التثبيت.

مخطط:
```
المطبعة                              مبنى الليزر
Windows 7 shop server                Windows 7 laser PC
إنترنت المطبعة                       هاتف hotspot
         |                                   |
         +----- Radmin VPN encrypted -------+
               network / two peers only
```

**ليس تدفقًا آليًا من TrendOS بعد**: سيتم اختبار ملفات وهمية أولًا، ثم — إذا نجح الربط وتأهلت صلاحيات الملفات والنسخ الاحتياطية — ينقل المشغل ملفات الشغل يدويًا، ولا يوجد أي تغيير في آلة الليزر نفسها أو أوامر الحفر.

## 2. خطوات إثبات صغير ومحدود (owner-operated; لا تنفيذ من GitHub)

1. افحص وجود اتصال إنترنت فعلي على الجهازين، مع عدم مشاركة hotspot مع أطراف غير معروفة. على جهاز الليزر افحص Wi-Fi والتوافق مع 2.4 GHz hotspot أو استخدم USB tethering إن كان تعريفه مدعومًا. لا تُوصل أي ماكينة قبل إتمام اختبار الملفات.
2. نزّل Radmin VPN **من الموقع الرسمي فقط** على الجهازين، وافحص التوقيع الرقمي وثبّتهما بعد نقطة استعادة/نسخة احتياطية مناسبة للـWindows7، خصوصًا على سيرفر المطبعة. قد يتغير مسار الشبكة مع ظهور كارت VPN جديد؛ لا تغيّر إعدادات الراوتر/الـIP المحلي.
3. في المطبعة: Radmin VPN → **Create network**؛ اختر اسم شبكة فريدًا وسرًا قويًا **لا تضعه في دردشة/GitHub**. في جهاز الليزر: **Join network** بالاسم والسر. تأكد أن جهازين فقط يظهران في الشبكة الخاصة.
4. استخرج عنوان **Radmin VPN IP** لكل جهاز من التطبيق (غالبًا `26.x.x.x` ولكن استخدم العنوان الفعلي). جرّب `ping` من قائمة التطبيق للطرف الآخر. نجاح ping لا يكفي لنجاح مشاركة الملفات.
5. لتجربة تبادل الملفات، أنشئ على **جهاز المطبعة** مجلد تجربة خاليًا من بيانات عملاء وليكن `C:\LaserTransferTest`، واجعله مشاركة محدودة **اسمها `LaserTest`**. استخدم حساب Windows محليًا غير إداري وكلمة مرور قوية، مع Share + NTFS permissions محدودة. راجع Windows Firewall: اسمح فقط من عنوان VPN الطرف الآخر إلى SMB TCP 445 على واجهة VPN بعد فحص سياسة النظام؛ **لا تعطّل الجدار الناري ولا تفتح مشاركة `Everyone` بلا كلمة مرور، ولا تسمح بتعرّض SMB للراوتر العام أو شبكة الضيوف**.
6. من جهاز الليزر جرّب فتح `\\<SHOP_RADMIN_IP>\LaserTest` في File Explorer، بالمستخدم المحدود؛ أنشئ `TEST-LASER-001.txt` ثم انسخه للمطبعة، وأرجع `TEST-LASER-REPLY.txt`. تحقق من الأحجام والمحتوى أو SHA-256. **أي فشل أو ضرورة استخدام SMBv1 قديم وغير مؤمن = توقف عن مشاركة الملفات، ولا تُضعف الإعدادات لمجرد نجاح الاتصال**.
7. اختبر انقطاع الهوتسبوت والعودة وتأكد من عدم ضياع أو تكرار الملفات؛ قس الاستهلاك والسرعة مع ملفات تجريبية وأحجام قريبة من DXF/PNG الحقيقي.
8. بعد التجربة فقط، أنشئ `Laser Inbox` و`Laser Returns` لكل أوردر وصلاحيات خاصة ودورة تسمية واضحة؛ **لا تحذف الأصل**. احتفظ بنسخ احتياطية مستقلة وتحقق من الاستعادة.

### استرجاع سريع
إذا تسبب عميل VPN أو تغيير sharing بمشكلة إنتاج: افصل VPN على الجهازين، أزل مشاركة `LaserTest` المؤقتة/قواعدها المحددة بعد توثيقها، واعد الإعدادات السابقة. لا تغيّر D1 أو Cloudflare أو TrendOS Workers أو المخزن المحلي. لا تفتح Remote Desktop/Radmin Server لأن الحاجة نقل ملفات فقط.

## 2A. تجربة المستخدم المطلوبة — نفس استعراض شبكة المطبعة والتحكم الاختياري في الشاشة (owner clarification, 2026-10-17)

**الاحتياج الذي حدده المالك الآن:** ليس مجرد `get/put` أو تبادل ملفات يدوي؛ عامل الليزر يريد استخدام **Windows Explorer / Computer** لفتح جهاز ملفات المطبعة بنفس سهولة استخدام Network Share سابقًا، وقد يحتاج **تحكمًا يشبه Windows Remote Desktop** في شاشة جهاز المطبعة. كلا الجهازين Win7؛ Ubuntu ما زال في البيت.

### وضع A — ملفّات المطبعة داخل Explorer (الأولوية)

- يعمل Radmin VPN كطبقة اتصال شبكي افتراضية فقط. يظهر عنوان VPN محدد لكل جهاز. على جهاز المطبعة: حدد **مشاركة مجلد شغل الليزر فقط** بحساب Windows مخصص محدود وصلاحيات Share + NTFS؛ لا مشاركة `C:\\` كاملًا.
- على جهاز الليزر افتح `Win + R` واكتب `\\<SHOP_VPN_IP>\LaserJobs` **بعد تفعيل مشاركة محمية ومراجعة الجدار الناري**؛ يمكن من `Computer → Map network drive` ربط نفس المسار بالحرف `Z:`، مع إعادة الاتصال عند تسجيل الدخول حسب حاجة التشغيل.
- قد لا يظهر الجهاز بالاسم في قائمة `Network`، لأن اكتشاف الشبكة والبث المحلي لا يعبران كل VPN؛ الوصول بعنوان الـVPN أو محرك أقراص mapped هو السلوك المطلوب ولا يعتمد على الاكتشاف.
- ملفات DXF / PNG / Corel وغيرها تفتح محليًا عند العامل، لكن وقت قراءة/حفظ الملف يعتمد على سرعة باقة الهاتف والشبكة والـLatency؛ نسخ ملف العمل محليًا ثم إعادة الإصدار النهائي يخفف انقطاع الاتصال ومخاطر تلف الملفات في التطبيقات القديمة.
- اختبار قبول: `Win+R` إلى UNC، فتح مجلد تجريبي، نسخ ملف وهمي في الاتجاهين والتحقق من حجمه/بصمته، إعادة توصيل Hotspot ثم ظهور حرف `Z:` بعد إعادة تسجيل الدخول، دون صلاحيات إدارية. **SMBv1/Guest/Public shares/disable-firewall: NOT ALLOWED.**

### وضع B — شاشة جهاز المطبعة بالكامل، عند الضرورة فقط

- **VPN وحده لا يفتح Remote Desktop.** Windows 7 **Professional/Ultimate/Enterprise** يستطيع استضافة Remote Desktop (RDP)؛ Home/Starter لا يستضيفه بشكل رسمي. جهاز الليزر يشغّل `mstsc` ويدخل عنوان VPN الخاص بجهاز المطبعة إذا توفرت نسخة Windows المناسبة، NLA، صلاحية مستخدم محدودة، وضبط firewall لحركة VPN فقط؛ **TCP 3389 لا يفتح على الراوتر أو الإنترنت**.
- **مهم تشغيليًا:** Windows 7 RDP يستعمل جلسة واحدة نشطة عادة؛ اتصال العامل عن بعد قد يفصل أو يقفل سطح مكتب مستخدم المطبعة المحلي، فلا تعتبره Remote Viewing متزامنًا. لذلك لا يفضّل كمسار تشغيل دائم إذا كمبيوتر المطبعة في استخدام شخص آخر.
- **Radmin Remote Control البديل:** يتطلب Radmin **Server** مرخصًا على جهاز المطبعة و**Viewer** على جهاز الليزر إضافة إلى Radmin VPN. يدعم Win7 والتحكم في نفس جلسة الشاشة، لكنه **ليس مجانيًا مثل Radmin VPN**؛ الرخصة القياسية المعلنة $49 لكل جهاز يُتحكّم فيه، والتحقق من السعر والترخيص عند الشراء مطلوب. المشاركة المتزامنة للماوس/الكيبورد بين موظفين قد تسبب تعارضًا.
- الاعتماد الأول: **وضع A** من Explorer؛ وضع B فقط عند وجود حاجة مثبتة وبعد التحقق من Edition وتأثير الجلسة على عمل بقية المطبعة.
- أمنًا، نظام Windows7 انتهى دعمه؛ هذا تخفيف مؤقت للمخاطر وليس تأهيلًا دائمًا، وخطة التحديث/العزل على شبكة مجزأة مطلوبة لاحقًا.

**مراجع:** [Radmin Help — VPN + full control](https://www.radmin-vpn.com/help/index.html)، [Radmin Server / Viewer installation](https://helpdesk.radmin.com/kb/faq.php?id=289)، [Radmin licenses](https://www.radmin.com/ordering/)، [Microsoft Windows 7 Remote Desktop host limitations](https://learn.microsoft.com/en-us/answers/questions/2435852/does-windows-7-home-version-have-remote-desktop-fu)، [Microsoft remote desktop security](https://learn.microsoft.com/en-us/windows-server/remote/remote-desktop-services/remotepc/remote-desktop-allow-access).

## 2B. إشغال جهاز المطبعة — وائل يعمل عليه طوال اليوم (مالك 2026-10-17)

**إفادة تشغيلية جديدة:** كمبيوتر Windows 7 الموجود بالمطبعة هو جهاز عمل وائل اليومي، وليس خادمًا شاغرًا للتحكم بسطح مكتبه. **قرار التشغيل: استخدام الجهازين بالتزامن من دون إيقاف جلسة وائل أو السيطرة على شاشة/فأرة عمله.**

- **المسار المعتمد للتجربة:** عامل الليزر يستخدم Explorer/Computer من جهاز Windows7 المنفصل. بعد تأمين Radmin VPN، يفتح مشاركة شغل الليزر المعزولة من جهاز وائل بمسار `\\<SHOP_VPN_IP>\LaserJobs` ويثبتها بحرف `Z:`. لا يحتاج العامل إلى جلسة Remote Desktop على جهاز وائل. يمكن لوائل الاستمرار في البرامج والعمل على ملفات غير مفتوحة للتحرير المشترك.
- **RDP ليس مناسبًا كاختيار افتراضي:** جلسات Windows 7 المكتبي قد تؤدي إلى قفل/فصل الجلسة المحلية، ما يعطّل وائل. لا نحاول ترقيع تعدد جلسات Windows7 أو تجاوز قيد التراخيص/الأمان.
- **Radmin full control ليس استقلالًا:** إذا كان مطلوبًا مشاهدة نفس الشاشة بموافقة وائل، يمكن بحث Radmin Server/Viewer لاحقًا؛ هو عرض وتحكم في نفس سطح المكتب، وسيشاهد الطرفان نفس المؤشر وقد يتعارضان. ليس حلًا لشخصين يريدان استعمال برنامجين مستقلين على جهاز واحد.
- **ملفات متزامنة:** لا يحرر وائل والعامل ملف التصميم نفسه في الوقت ذاته؛ ملفات `Working` منفصلة وإرجاع إلى `Returns` بعد الحفظ ومراجعة النسخة. فتح ملفات كبيرة مباشرة من الشبكة عبر هوتسبوت قد يكون بطيئًا أو معرضًا لفشل الحفظ؛ يفضّل نسخ الملف محليًا ثم رفع الناتج وربطه برقم الأوردر.
- **برامج الويب المحلية:** إن كان العامل سابقًا يفتح واجهة بمتصفح `http://<shop-host>:<port>`، فهذا **خدمة شبكة مستقلة** عن Remote Desktop. الوصول عبر VPN يتطلب فحص عنوان الاستماع، firewall، صلاحيات التطبيق، وسماح اتصال من peer، وقد يسمح باستعمال متزامن إذا كانت الواجهة تدعم عدة مستخدمين. لا تغيير لخدمات وائل أو منافذ البرنامج قبل معرفة البرنامج ومكان تشغيله.
- **ما يلزم لإثبات القبول:** شبكة VPN نقطية = PASS، مشاركة مقيدة بحرف `Z:` قابلة للقراءة/الكتابة وفق الصلاحيات، اختبار ملفين وهميين واتساق SHA256، اختبار أن وائل يواصل جلسة شغله أثناء فتح المجلد عند الليزر، فصل الهوتسبوت وإعادة وصله، وعدم تغيير جلسة/إعدادات برامج وائل.

**Status:** `WAEL_SHOP_PC_ACTIVE_USER=OWNER_VERIFIED`, `DESKTOP_TAKEOVER=NOT_PERMITTED_AS_DEFAULT`, `INDEPENDENT_LASER_EXPLORER_WORKFLOW=DESIGN_ONLY`, `LIVE_VPN_AND_SHARE=NOT_VERIFIED`; **no installation, deployment, Win7 setting, or customer file mutation done by assistant**.

## 3. أمان Windows 7 — حد أساسي

- Microsoft أوقفت دعم Windows 7 يوم **14 يناير 2020**؛ ماكينات الإنتاج العاملة به لا ينبغي تعريضها للإنترنت أو توسيع صلاحياتها بشكل دائم. Radmin VPN *يضيف شبكة خاصة مشفرة* ولكنه **لا يعالج ثغرات نظام التشغيل، SMB، أو سرقة بيانات الاعتماد**. اجعل الاتصال نطاقًا ضيقًا ومؤقتًا، وخطط لجهاز gateway حديث منفصل أو تحديث منصة غير مرتبطة ببرنامج الليزر إذا استحال ترقية الجهاز نفسه.
- لا تعطل Firewall أو antivirus، ولا تستخدم share بكلمة مرور فارغة، ولا تعرض كامل القرص، ولا توصل كل أجهزة LAN خلف VPN. **SMBv1 ممنوع في المسار الجديد**؛ حتى لو كان مطلوبًا تاريخيًا لجهاز/برنامج آخر، لا تفعله لإصلاح اختبارنا. يمكن استخدام اتصال ملفات عبر بوابة Linux حديثة ذات SFTP لاحقًا إن أردنا عزل الـWindows7؛ لكن Ubuntu الموجود في البيت لا يحل محل بوابة قائمة بالمطبعة دون تركيب/تخطيط منفصل.
- بعض شبكات الموبايل تعمل NAT/CGNAT، وقد تصبح وصلة Radmin VPN Relay/TCP؛ اختبر عمليًا ولا تفترض سرعات عالية أو اتصالًا مباشرًا. نقل الملفات عبر الإنترنت يستهلك من باقة الهاتف.

## 4. الأنظمة الأخرى وملاحظات على الوثيقة السابقة

- **Cloudflare Mesh ليس حلًا مباشرًا لجهازي Windows 7:** عميل Cloudflare One الحديث لا يدعم Windows 7، ولا يوجد Ubuntu في المطبعة أو مبنى الليزر حاليًا. لا تعمل Installation على Windows7 لعميل غير مدعوم، ولا تستخدم Workers/D1 أو أدوات TrendOS السحابية كجسر لنقل صور العملاء.
- **Ubuntu TrendosShop في البيت:** السجل السابق لكتابي Ubuntu والمطبعة الذاتية يظل صحيحًا بالنسبة لاختبار هذا المضيف مستقلًا؛ لا يدّعي ارتباطه بمبنى الليزر. ملف `src/config.py` يتضمن مسار `laser` على مستوى **source only**؛ لا توجد خدمة توزيع أوردرات مثبتة Production.
- **PtP wireless bridge** قد يكون بديلًا مستقبليًا إذا المالك سمح بحل لاسلكي وتركيب أجهزة واتضحت الرؤية بين المبنيين؛ ليس جزءًا من تجربة الهوتسبوت الحالية، ولا نحتاج تمديد أسلاك بين المبنيين.
