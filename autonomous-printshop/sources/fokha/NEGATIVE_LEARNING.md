# Fokha Negative Learning — Global Only

> أخطاء ومخاطر عامة قابلة لإعادة الاستخدام بين المشاريع.
> Updated: 2026-09-12.

## Global lessons

- تجنب إعادة بناء نظام إنتاج شغال بالكامل بدون ضرورة؛ افحص أولًا ثم نفذ تغييرًا صغيرًا وقابلًا للرجوع.
- نجاح الكود أو CI أو النشر لا يساوي إثبات Production؛ يلزم Runtime Evidence.
- لا تحسن جزءًا محليًا قبل تحديد عنق الزجاجة الحقيقي في المسار الكامل.
- لا تستخدم بيانات أو أصولًا أو مصادر غير مرخصة في أي مشروع.
- لا تحفظ API keys أو tokens أو passwords أو credentials داخل Repository عام أو Frontend.
- الفشل الصحيح لا يُمحى؛ يُحتفظ به كدليل يساعد على منع تكرار الخطأ.

## Project-specific negative learning

لا يُحفظ هنا. يبقى داخل ذاكرة المشروع الذي حدث فيه.
